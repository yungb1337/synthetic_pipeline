One architectural change I would make

There's one addition I would make to your design that I think will pay off significantly later:
introduce a canonical "Document Object Model" (DOM--not the HTML DOM)
immediately after parsing and before normalization.

Instead of each downstream module reading raw parser output, every parser should
produce the same structured representation:

    Document
     Metadata
     Pages
      Blocks
      Paragraphs
      Tables
      Images
      Coordinates
     References
     Version

Every subsequent module--normalization, chunking, entity extraction, table processing,
and knowledge extraction--operates on this single internal format. That gives you parser
independence: you can swap PDF libraries, improve OCR, or add DICOM support later
without rewriting the rest of the pipeline. This is a pattern used in many mature document
intelligence systems because it decouples document ingestion from knowledge extraction.

This approach has several advantages:
      The document is read only once.
      All extractors reuse the same in-memory page representation.
      The output is a single, consistent data model that every downstream module
      understands.
      Adding support for a new file type (for example, DICOM or CAD drawings) only
      requires writing a new extractor that produces the same Document object. None of
      the downstream AI pipeline needs to change.

That is much closer to how production-grade document intelligence systems are
engineered than treating every step as an independent parser.

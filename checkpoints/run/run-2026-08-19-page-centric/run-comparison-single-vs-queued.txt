2) WHAT ACTUALLY DIFFERS (and why it is benign)
--------------------------------------------------------------------------------
Pairwise deep-diff of all 15 DOMs found THREE fields differing, all in
`.provenance` (metadata, never in the recovered data):

  a) .provenance.routing.inspection_time_ms  -> 12 docs
       A pure wall-clock timing of the router inspection. Non-deterministic by
       nature; carries no document content.

  b) .provenance.routing.signals[8].value / .evidence  -> 1 doc (d-9265...)
       The `metric_text_ratio` routing signal: 0.130 (single) vs 0.110 (queued).
       This is a routing signal derived from OCR-extracted text. OCR (rapid-ocr
       onnxruntime) is non-deterministic across process invocations, so the
       ratio wobbles — yet the ROUTE DECISION was identical (both `enrichment`)
       and the final recovered DOM content is byte-identical.

  c) 3 docs had NO diff at all (d-41bcd..., d-8e9a..., d-fa25...) — fully equal
     DOM files.

CONCLUSION: the only non-determinism is in (1) a router timing field and
(2) one OCR-derived routing *signal value* whose downstream decision is stable.
The actual extracted DOM — headings, paragraphs, tables, OCR text, page count —
is reproducible between "parse each file alone" and "parse the whole folder at
once". The OOM-hardening (page-centric) design therefore produces
run-to-run-equivalent output regardless of whether you queue the directory or
feed files one at a time.
